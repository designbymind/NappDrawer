# Napp Drawer Module

## Description

The Napp Drawer module extends the Appcelerator Titanium Mobile framework.
The module is licensed under the MIT license.

Thanks to the folks at Mutual Mobile for their great work with MMDrawerController https://github.com/mutualmobile/MMDrawerController


### Get the module

Download the versioned iOS ZIP from GitHub Releases. Local builds are produced
in `ios/dist/`. See [the changelog](../CHANGELOG.md) for all changes since 3.2.1;
3.6.6 adds scale controls and stable rounded corners; 3.6.5 includes the earlier
intermediate local-build updates, including 3.6.4.

## Referencing the module in your Ti mobile application

NappDrawer requires iOS 18.0 or later. Set `<min-ios-ver>18.0</min-ios-ver>`
inside your app's `<ios>` section to support iOS 18+. Use a current Xcode with
an iOS 26+ SDK for development. The deployment target is independent of that
SDK version; iOS 26-only features retain runtime availability checks.

Simply add the following lines to your `tiapp.xml` file:

```xml
<modules>
  <module platform="iphone">dk.napp.drawer</module>
</modules>
```

## Reference

For more detailed code examples take a look into the example app.

### centerWindow, leftWindow, rightWindow

Napp Drawer does not require you to use the three windows. You can also use either the combo of center/left or center/right for your desired needs.

```javascript
var mainWindow = NappDrawerModule.createDrawer({
  centerWindow: navController,
  leftWindow: winLeft,
  rightWindow: winRight,
  closeDrawerGestureMode: NappDrawerModule.CLOSE_MODE_ALL,
  openDrawerGestureMode: NappDrawerModule.OPEN_MODE_ALL,
  leftDrawerWidth: 180,
  rightDrawerWidth: 220,
  statusBarStyle: NappDrawerModule.STATUSBAR_WHITE,
  orientationModes: [Ti.UI.PORTRAIT, Ti.UI.UPSIDE_PORTRAIT]
});
```

## API Properties

### Initial drawer side (3.6.3+)

```javascript
var drawer = NappDrawerModule.createDrawer({
  centerWindow: centerWindow, // Still required.
  leftWindow: leftWindow,
  rightWindow: rightWindow,
  initialDrawerSide: 'left' // 'center' (default), 'left', or 'right'.
});
drawer.open();
```

The chosen side starts open at its configured width before the controller view
is attached for presentation. No opening animation, haptic, `sliding`, or
`drawerTransition` event is generated by this initial positioning; normal window
lifecycle events continue. Side-specific animation styles, the center border,
and attached-sheet position are initialized for the chosen state. If the
requested side has no window, the module warns and starts centered.

Set this property in `createDrawer()`. Changing it after creation does not move
the drawer; use the regular drawer controls for runtime changes. The center
window remains required. With `center`, existing default behavior is preserved.

### CenterWindow, leftWindow, rightWindow

A method that allow change of a window. You can either use a window or a navigation group.
```javascript
var newWin = Ti.UI.createWindow({
  backgroundColor: '#FF0000'
};
mainWindow.setCenterWindow(newWin);
```

If you want to remove the side drawer, you can do this be parsing false as the argument.
```javascript
mainWindow.setRightWindow(false);
```

### LeftDrawerWidth, rightDrawerWidth

Update the width with these methods. The default width is `280`

```javascript
mainWindow.setLeftDrawerWidth(160);
```

With animation:

```javascript
mainWindow.setLeftDrawerWidth({
  width: 160,
  animated: true
});
```

### Haptics and transition events (3.6.0+)

```javascript
drawer.hapticFeedback = 'gesture'; // 'none' (default), 'gesture', or 'all'.
drawer.hapticStyle = 'light';      // light, medium, heavy, soft, or rigid.
drawer.addEventListener('drawerTransition', function(e) {
  Ti.API.info(e.state + ': ' + e.side + ' (' + e.source + ')');
  // state: opening, closing, open, closed.
  // side: left or right, including after closing.
  // source: gesture or programmatic, retained through completion.
});
```

Both properties support creation-time and live assignments. `gesture` produces
one native impact when releasing a pan starts the automatic settling animation.
`all` also covers tap-to-close and programmatic open/close, including meaningful
nonanimated changes. There is no second completion impact. Cancelled pans settle
as gesture transitions but do not generate feedback. Actual feedback requires a
device that supports haptics and remains subject to system settings.

Events work independently of haptic settings or hardware. `opening`/`closing`
announce the chosen destination as the finishing animation begins;
`open`/`closed` are emitted only on successful completion. A tap-to-close is a
gesture source. Width resizing, bounce previews, rejected requests, and requests
already at their destination do not emit these transition events or impacts.
Existing window lifecycle events and `sliding` continue unchanged.

### Animated width changes (3.5.0+)

The explicit JavaScript methods `setLeftDrawerWidth()` and `setRightDrawerWidth()`
are exported starting with 3.6.1. Earlier builds have native property setters but
do not export these method names. Property assignment works through the same path:

Use 3.6.2 or later: 3.6.1 eagerly creates the native view from these setters,
including during creation-time property application, which can cause a launch
hierarchy exception. 3.6.2 keeps initialization lazy and preserves the exports.

```javascript
mainWindow.leftDrawerWidth = { width: mainWindow.rect.width, animated: true };
mainWindow.rightDrawerWidth = { width: mainWindow.rect.width - 64, animated: true };
```

An open drawer can expand and contract while its attached sheet follows:

```javascript
mainWindow.setLeftDrawerWidth({
  width: mainWindow.rect.width, // Target width in points; full window width.
  animated: true               // Animate the drawer and attached sheet together.
});
// Restore your previous width using the same method.
mainWindow.setLeftDrawerWidth({ width: mainWindow.rect.width - 64, animated: true });
```

Use `setRightDrawerWidth` for the right side. Sheet following requires
`followsPresentedSheet` and an attached center sheet; sheets presented from side
drawers remain independent. Closed-drawer width changes do not emit resize events.
During movement the latest pending width request is retained and applied afterward.
Drawer pans/open/close are blocked during the resize animation, matching the
existing open/close animation guard. No new window open/close events are generated
by a resize. Native border fading stays fully visible while a fully open drawer resizes.

The `sliding` event now includes these fields on ordinary movement and resizing:

```javascript
mainWindow.addEventListener('sliding', function(e) {
  Ti.API.info(JSON.stringify({
    progress: e.progress,         // Open fraction, 0–1; stays 1 during a fully open resize.
    side: e.side,                 // 'left' or 'right'.
    resizing: e.resizing,         // True during an open-drawer width change; false at completion.
    drawerWidth: e.drawerWidth,   // Current animated drawer width in UIKit points.
    centerOffset: e.centerOffset  // Center displacement in points: positive left, negative right.
  }));
});
```

The original `progress` and `side` meanings are preserved. Geometry changes emit
updates even when progress is unchanged, followed by a final `resizing: false`
event. Width animation duration continues to use the module's `animationVelocity`.

### Shadow appearance

`showShadow` enables the center's shadow. Configure it at creation or afterward:

```javascript
drawer.showShadow = true;
drawer.shadowRadius = 10; // Blur radius in points; minimum 0.
drawer.shadowColor = '#000000';
drawer.shadowOpacity = 0.8; // Clamped to 0–1.
```

These are the existing visual defaults. Disabling `showShadow` hides the shadow
without discarding its configured values. The values survive center-window
replacement and corner-mode changes. The shadow remains outside the center's
clipping surface; its existing offset is unchanged.

### Root background color

`rootBackgroundColor` controls the internal drawer root behind the center and
side windows. It defaults to black and can be set at creation or updated later:

```javascript
mainWindow.rootBackgroundColor = '#f5f5f5';
```

Use `'transparent'` to reveal the side drawer where it occupies the exposed area,
or otherwise the outer Titanium drawer view and its parent background. This does
not change hit testing. Set the outer `backgroundColor` as well if you want a
specific color beneath a transparent root.

### Center corners and border

These optional properties style the entire center window, including its
NavigationWindow. The defaults preserve square corners and no border.

```javascript
var drawer = NappDrawerModule.createDrawer({
  // ...leftWindow, centerWindow, rightWindow...
  rootBackgroundColor: '#eee',
  centerCornerMode: 'concentric',
  centerCornerRadius: 32, // Continuous fallback on iOS 18–25.
  centerBorderWidth: 1,
  centerBorderColor: '#888',
  centerBorderOpacity: 0.8,
  centerBorderFollowsSliding: true
});
```

`continuous` uses a smooth squircle-style curve with `centerCornerRadius` in
points. In 3.6.6, `concentric` resolves UIKit's public container-concentric
radius on iOS 26+ using an invisible, non-interactive measurement view at the
center's aligned resting geometry. The real center, border, and shadow use that
fixed radius, so moving the center does not flatten its corners. This also works
with `initialDrawerSide: 'left'` or `'right'` without visibly repositioning the
center or requiring a JavaScript radius query. The measurement is refreshed on
appearance/layout for window geometry changes. Until attached/layout is available,
or if UIKit reports no positive radius, `centerCornerRadius` is the fallback.
It is not a getter for the physical screen radius. On older iOS the configured
continuous fallback radius is used directly.

The border follows the same corner configuration as the clipping surface and
does not intercept touches. The center's shadow remains outside the clipping
surface. You can update all properties after creation, including after changing
`centerWindow`.

`centerBorderFollowsSliding` animates the outline opacity using the drawer's
native duration/curve and updates it directly during dragging. It needs no JS
`sliding` listener. For a custom effect, leave that option false and use the event:

```javascript
drawer.addEventListener('sliding', function(e) {
  drawer.centerBorderOpacity = e.progress;
  // Optional: grow a continuous radius while opening.
  // drawer.centerCornerRadius = 32 * e.progress;
});
```

`centerCornerMode: 'none'` disables module-provided rounding, and
`centerBorderWidth: 0` disables the border. Square corners remain the default;
no measurement view is created unless concentric rounding is enabled.
`centerCornerRadius` is a fallback in concentric mode; use `continuous` to
control the radius explicitly on every supported iOS version.

Read the resolved radius after the drawer is open and laid out:

```javascript
var radius = drawer.getCenterCornerRadius();
Ti.API.info('Resolved center corner radius: ' + radius + 'pt');
```

The return value is a number in UIKit points, not pixels. In concentric mode on
iOS 26+, it reports the applied stable radius resolved from aligned geometry
(or the fallback), even while a side drawer is open. In continuous mode
or on iOS 18–25 it reflects the continuous radius. It returns `0` when rounding
is disabled or the drawer is not attached to a window. Query again after layout
or mode changes if you need an updated value. `centerCornerRadius` remains the
configured input; this method does not read a private physical-screen-radius API.

### CenterHiddenInteractionMode

Set different types of interactivity for the centerWindow.

```javascript
mainWindow.setCenterHiddenInteractionMode(NappDrawerModule.OPEN_CENTER_MODE_FULL);
```

| input (constant) | Description |
| ----- | ----------- |
| OPEN_CENTER_MODE_NONE | The user can not interact with any content in the center view. |
| OPEN_CENTER_MODE_FULL | The user can interact with all content in the center view. |
| OPEN_CENTER_MODE_NAVBAR | The user can interact with only content on the navigation bar. The setting allows the menu button to still respond, allowing you to toggle the drawer closed when it is open. This is the default setting. |


### OpenDrawerGestureMode

Set gesture support for opening the drawer through a mask.

```javascript
mainWindow.setOpenDrawerGestureMode(NappDrawerModule.OPEN_MODE_BEZEL_PANNING_CENTERWINDOW);
mainWindow.openDrawerBezelWidth = 40; // Points from either available drawer's screen edge.
```

| input (constant) | Description |
| ----- | ----------- |
| OPEN_MODE_NONE | The user can not open the drawer by panning. |
| OPEN_MODE_ALL | The user can open the drawer by panning anywhere. |
| OPEN_MODE_PANNING_NAVBAR | The user can open the drawer by panning anywhere on the navigation bar. |
| OPEN_MODE_PANNING_CENTERWINDOW | The user can open the drawer by panning anywhere on the center view. |
| OPEN_MODE_BEZEL_PANNING_CENTERWINDOW | The user can open the drawer by starting a pan within `openDrawerBezelWidth` points of the bezel (default: 20). |

`openDrawerBezelWidth` can be supplied to `createDrawer()` or assigned at runtime.
Use `0` to disable bezel opening; negative values clamp to zero and non-finite
values reset to 20. Widths larger than the container are capped to its width.
Closing gestures are unchanged. Broader modes such as `OPEN_MODE_ALL` and
`OPEN_MODE_PANNING_CENTERWINDOW` still allow opening outside the bezel.
Attached-sheet edge zones remain controlled separately by `presentedSheetEdgeWidth`.


### CloseDrawerGestureMode

Set gesture support for closing the drawer through a mask.

```javascript
mainWindow.setCloseDrawerGestureMode(NappDrawerModule.CLOSE_MODE_TAP_CENTERWINDOW);
```

| input (constant) | Description |
| ----- | ----------- |
| CLOSE_MODE_NONE | The user cannot close the drawer by any panning gestures. |
| CLOSE_MODE_ALL | The user can close the drawer by panning anywhere. |
| CLOSE_MODE_PANNING_NAVBAR | The user can close the drawer by panning anywhere on the navigation bar. |
| CLOSE_MODE_PANNING_CENTERWINDOW | The user can close the drawer by panning anywhere on the center view. |
| CLOSE_MODE_BEZEL_PANNING_CENTERWINDOW | The user can close the drawer by starting a pan within `closeDrawerBezelWidth` points of the screen edge containing the exposed center view (default: 20). |
| CLOSE_MODE_TAP_NAVBAR | The user can close the drawer by tapping the navigation bar. |
| CLOSE_MODE_TAP_CENTERWINDOW | The user can close the drawer by tapping the center view. |
| CLOSE_MODE_PANNING_DRAWER | The user can close the drawer by panning anywhere on the drawer view. |

*Note that these gestures may impact touches sent to the child view controllers, so be sure to use these appropriately for your application.*

In 3.6.5+, configure independent bezel widths at creation or runtime:

```javascript
mainWindow.openDrawerGestureMode = NappDrawerModule.OPEN_MODE_BEZEL_PANNING_CENTERWINDOW;
mainWindow.closeDrawerGestureMode = NappDrawerModule.CLOSE_MODE_BEZEL_PANNING_CENTERWINDOW;
mainWindow.openDrawerBezelWidth = 40;
mainWindow.closeDrawerBezelWidth = 60;
```

Closing uses the right screen edge when the left drawer is open and the left
screen edge when the right drawer is open, intersected with visible center
content (navigation bars excluded), matching the original bezel behavior.
Both widths default to 20 points. Zero disables only that bezel mode; negative
values clamp to zero, non-finite values reset to 20, and hit testing caps widths
to the container. Broader enabled modes such as `CLOSE_MODE_ALL` remain
unrestricted. Attached-sheet gesture-shield behavior is unchanged; these widths
apply to the normal center-window recognizer, not the separate sheet shield.

### AnimationMode

Starting with iOS module 3.4.0, each side can optionally override the shared mode:

```javascript
mainWindow.animationMode = NappDrawerModule.ANIMATION_SLIDE;
mainWindow.leftAnimationMode = NappDrawerModule.ANIMATION_PARALLAX_FACTOR_7;
mainWindow.rightAnimationMode = NappDrawerModule.ANIMATION_SLIDE;

// Clear an override to follow the shared animationMode again.
mainWindow.leftAnimationMode = null;
```

Both overrides accept the same constants as `animationMode`, at creation or
afterward. An unset override preserves the original shared behavior. Changing
`animationMode` does not discard a side override; clear it with `null` first.
The selected effect is used for the side's subsequent visual-state updates,
including dragging and programmatic open/close. `animationVelocity` remains
shared. The overrides are iOS-only.

Set the overall animation of the side windows when opening and closing the drawer.

```javascript
mainWindow.setAnimationMode(NappDrawerModule.ANIMATION_SLIDE);
```

| input (constant) | Description |
| ----- | ----------- |
| ANIMATION_NONE | No animation |
| ANIMATION_SLIDE | The side window will slide in at the same speed as the drawer. This is equivalent to a parallax effect with factor 1 (no parallax effect).  |
| ANIMATION_PARALLAX_FACTOR_3 | The slide animation, but with a parallax effect. The higher factor equals less animation distance rate. This is 3 times slower than ANIMATION_SLIDE. |
| ANIMATION_PARALLAX_FACTOR_5 | The slide animation, but with a parallax effect. The higher factor equals less animation distance rate. This is 5 times slower than ANIMATION_SLIDE. |
| ANIMATION_PARALLAX_FACTOR_7 | The slide animation, but with a parallax effect. The higher factor equals less animation distance rate. This is 7 times slower than ANIMATION_SLIDE. |
| ANIMATION_FADE | Fading out/in the side window. |
| ANIMATION_SLIDE_SCALE | The Side window will slide and scale simultaneously. |
| ANIMATION_SCALE | Scale the side window without translation; optionally fade using `animationScaleFade`. |

### AnimationMinScale (3.6.6+)

```javascript
mainWindow.animationMode = NappDrawerModule.ANIMATION_SLIDE_SCALE;
mainWindow.animationMinScale = 0.95; // Subtler than the backward-compatible 0.90 default.
```

Set `animationMinScale` at creation or runtime. It controls side-drawer scaling,
not center-window scaling, and applies when the shared mode or a per-side
override uses `ANIMATION_SLIDE_SCALE` or `ANIMATION_SCALE`. Scale interpolates from this value to 1
as opening progress reaches 1. A value of 1 disables scaling, but leaves the
mode's translation and fading intact. Values clamp to 0–1; non-finite values
reset to 0.90. Runtime changes are read on subsequent visual updates, without
resetting mode overrides. Other animation modes are unaffected.

### Scale-only animation (3.6.6+)

```javascript
mainWindow.animationMode = NappDrawerModule.ANIMATION_SCALE;
mainWindow.animationMinScale = 0.95;
mainWindow.animationScaleFade = true; // Optional; defaults to false for pure scale.
```

`ANIMATION_SCALE` scales the side drawer in place; it does not add the side
translation used by `ANIMATION_SLIDE_SCALE`. The center still moves normally to
reveal the drawer. By default the side stays opaque; `animationScaleFade: true`
adds fading with opening progress. Scale/fade progress is capped at 0–1 during
overshoot. Both properties support creation-time and runtime assignments and
per-side mode overrides. `animationScaleFade` affects only `ANIMATION_SCALE`;
the existing slide-scale mode retains its original translation and fading.

### AnimationVelocity

The animation velocity of the open and close methods, measured in points per second.
By default, this is set to 840 points per second (three times the default drawer width), meaning it takes 1/3 of a second for the `Window` to open/close across the default drawer width. Note that there is a minimum .1 second duration for built in animations, to account for small distance animations.

```javascript
mainWindow.setAnimationVelocity(400);
```

### ShowShadow

Should the shadow be visible?

```javascript
mainWindow.setShowShadow(true);
```

### ShouldStretchDrawer

A small effect when the drawer is dragged, the drawer stretches.

```javascript
mainWindow.setShouldStretchDrawer(true);
```

### FollowsPresentedSheet

Opt in to coordinating the currently presented native
`UISheetPresentationController` with the drawer's center window. The default
is `false`.

```javascript
mainWindow.setFollowsPresentedSheet(true);
```

### PresentedSheetEdgeWidth

Set the width of each edge zone that can open a drawer over an attached,
undimmed sheet. The default is `32`. Set it to `0` to opt out entirely. This
property has no effect at a dimmed detent, where drawer opening is
programmatic-only.

```javascript
mainWindow.setPresentedSheetEdgeWidth(0);
```

### OrientationModes

Use this property to restrict the drawer to a certain set of orientations. You can use any of Titanium's orientation constants defined in Ti.UI. (LANDSCAPE_LEFT, LANDSCAPE_RIGHT, PORTRAIT, UPSIDE_PORTRAIT).

```javascript
mainWindow.setOrientationModes([Ti.UI.PORTRAIT, Ti.UI.UPSIDE_PORTRAIT]);
```

### StatusBarStyle

Use this property to set the statusBar. You will need to add the following to tiapp.xml in order to make this work:

```xml
<ios>
  <plist>
    <dict>
      <key>UIViewControllerBasedStatusBarAppearance</key>
      <false/>
    </dict>
  </plist>
</ios>
```

| input (constant) | Description |
| ----- | ----------- |
| STATUSBAR_BLACK | The statusbar icons and text will be black |
| STATUSBAR_WHITE | The statusbar icons and text will be white |

```javascript
mainWindow.setStatusBarStyle(NappDrawerModule.STATUSBAR_WHITE);
```

### Alternative method

If your drawer has a rightWindow, you can also set the statusbarStyle off that window, which will automagically apply that style to all of the drawer. This was discovered by Andrea Vitale.

```javascript
rightWindow: Ti.UI.createWindow({
  statusBarStyle: Ti.UI.iPhone.StatusBar.LIGHT_CONTENT
});
```

## API Methods

### toggleLeftWindow, toggleRightWindow

`toggleLeftWindow()` and `toggleRightWindow()` are used to toggle each visibility of either the left or right window.

```javascript
mainWindow.toggleLeftWindow();
```

### bounceLeftWindow, bounceRightWindow

A small animation to show the app user that its possible to interact with the drawer.

```javascript
mainWindow.bounceLeftWindow();
```

### isAnyWindowOpen, isLeftWindowOpen, isRightWindowOpen, isAnySheetOpen

Check if a side or any window is opened in the drawer, or if a native sheet is
currently presented.

```javascript
mainWindow.isAnyWindowOpen();
mainWindow.isAnySheetOpen();
```

### attachPresentedSheet, detachPresentedSheet

Attach after the native sheet opens and detach when it closes. NappDrawer does
not depend on a specific bottom-sheet module.

```javascript
sheet.addEventListener('open', function() {
  mainWindow.attachPresentedSheet();
  Ti.API.info('Any sheet open: ' + mainWindow.isAnySheetOpen());
});

sheet.addEventListener('close', function() {
  mainWindow.detachPresentedSheet();
});
```

While the drawer is closed at an undimmed sheet detent, the attached sheet
remains interactive except for narrow left and right edge-swipe zones used to
open a drawer. At a dimmed detent, drag-to-open is disabled and the drawer can
only be opened programmatically. While a drawer is moving or open, touches to
that attached sheet are temporarily blocked and the drawer can still be closed
by its configured pan or tap gestures. A sheet presented independently from a
left or right drawer is not attached or blocked automatically.

## Events

### windowDidOpen

When the drawer has been opened.

```javascript
mainWindow.addEventListener('windowDidOpen', function(e) {
  // Drawer opened
});
```

### windowDidClose

When the drawer has been closed.

```javascript
mainWindow.addEventListener('windowDidClose', function(e) {
  // Drawer closed
});
```

### centerWindowDidFocus

When the drawer center window has been focussed.

```javascript
mainWindow.addEventListener('centerWindowDidFocus', function(e) {
  // Center window focussed
});
```

When the drawer center window has been blurred.

```javascript
mainWindow.addEventListener('centerWindowDidBlur', function(e) {
  // Center window blurred
```
